# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Raycast extension for JA ⇄ EN translation. By default it auto-detects a local PLaMo 3 Translate model served by LM Studio (`localhost:1234`) or Ollama (`localhost:11434`); "Choose Model" switches to any OpenAI-compatible LLM or DeepL. User-facing strings (UI, toasts, `package.json` descriptions, README) are in Japanese; code comments are in English.

## Commands

```bash
npm run dev        # ray develop: registers the dev extension in Raycast (it stays after Ctrl+C)
npm test           # vitest run
npx vitest run test/servers.test.ts   # single file
npx vitest run -t "pattern"           # single test by name
npm run lint       # eslint + prettier --check (fix-lint to auto-fix)
npm run typecheck  # tsc --noEmit
```

`raycast-env.d.ts` (the `Preferences` / `Arguments` types) is generated by `ray develop`/`ray build` from `package.json`. After changing preferences or command arguments in `package.json`, run `npm run dev` once so the types regenerate.

## Architecture

- **Commands** (`src/*.tsx`, `src/translate-*.ts`): `index` is the live-translating form; the three no-view commands are thin wrappers around `quickTranslate()` in `src/lib/quick-translate.ts`, which reads input (`source.ts`: selection or clipboard, with fallback), resolves the target, and copies / pastes / or hands off to `index` via `launchCommand` + `launchContext` when the "view" action is chosen.
- **Backend selection** (`src/lib/translate.ts`): `getBackend()` uses the "Choose Model" selection stored in Raycast `LocalStorage` (`selection.ts`); with none, it auto-detects PLaMo via `servers.ts` and caches that promise for the life of the command (reset on failure so a restarted server is re-detected). The prompt format is chosen by **model name**: anything matching `/plamo-3-translate/i` gets the PLaMo backend, everything else the generic LLM backend.
- **Backends** (`src/lib/backends/`) implement `Backend` from `types.ts`. `plamo.ts` and `llm.ts` both go through `openai-chat.ts` (SSE streaming via `onPartial`, `<think>` stripping, error → `TranslationError` with a Japanese `hint`). DeepL does not stream.
- **PLaMo protocol**: LM Studio / Ollama cannot forward `chat_template_kwargs`, so settings go in a leading system message `[plamo-translate]\nkey=value…` that the GGUF chat template parses. The template rejects unknown keys and invalid values; `form` (`polite`/`plain`) is only valid with `target_lang=ja`. The template also accepts `target_lang=ja(easy)` (やさしい日本語). Generation must stop on `<|plamo:tag|>` / `<|plamo:bos|>`.
- **Server discovery** (`servers.ts`): probes LM Studio's native `/api/v0/models` first (gives model type and loaded state), then falls back to `/v1/models`. `pickPlamoModel` prefers a loaded model, then the smallest. Only the custom server from preferences gets an API key.
- **Form ↔ full view** (`live-translation.ts`): `Action.Push` renders its target once with push-time props, so streaming state lives in a module-level store read via `useSyncExternalStore` by both the form and the pushed `TranslationDetail`. `parallel.ts` builds the side-by-side Markdown table (aligned by line, else by paragraph, else fall back to stacked).
- **Auto direction** (`detect.ts`): Japanese chars are weighted ×3 against Latin letters; text with no Japanese goes to `ja`.

## Tests

Vitest aliases `@raycast/api` to `test/raycast-api.ts` (in-memory `preferences` and `LocalStorage`; call `resetRaycast()` between tests). Network is stubbed with `mockFetch` / `json` / `sse` in `test/fetch.ts`, which records request bodies for assertions. Only `src/lib` is unit-tested; React commands are not.
